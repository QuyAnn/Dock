# SmartDock RAM optimization

Changes preserve drawing recipes, image resolution, layout and widget actions. Open calendar weather also requests its worker when dock weather is disabled. No working-set trimming is used. Savings below are allocation estimates, not a measured new process total; the original SmartDock process was left running.

| Change | Expected saving / bound |
| --- | --- |
| One scheduler replaces six permanent widget polling threads; blocking jobs run independently, at most one in flight per source, and exit between polls. Jobs follow placed widgets plus open popup/gallery previews. Weather in the clock, shared weather consumers, and Control Center media remain supported. Screen-time remains opt-in. | Removes sleeping worker stacks and avoids starting unused WMI, screenshot, finance, AI, weather and GPU work. Native API savings depend on enabled widgets. Stack reservation is **not** equivalent to private bytes. |
| Scheduler/audio/volume threads use 256 KiB stacks; blocking jobs, wallpaper, tray, desktop glass and live controls use 512 KiB. Temporary COM apartments are balanced on exit. | Compared with Rust's usual 2 MiB thread stack reservation: 1.5–1.75 MiB less reserved per affected thread; committed RAM saving is workload dependent and smaller. |
| Battery, network, disk and GPU sampling are individually gated. Removing GPU closes its PDH query; disabling network drops its baseline. CPU/RAM sampling and the 30 fps media repaint timer also follow demand. Control Center polls Bluetooth/DDC brightness only while its panel/preview needs them. | Avoids potentially substantial PDH/driver and WinRT allocations when their widgets are absent; no fabricated MB estimate. |
| Popup, gallery and Control Center share the existing popup HWND. Hide/swap releases its D2D target, GPU bitmap cache, CPU backdrop and glass pieces. Thumbnails release their target/cache on hide. Hidden paints cannot recreate surfaces. | Several MiB per previously opened surface; scales with physical window size/DPI. A single 1440×940 RGBA surface is 5.16 MiB, before driver/back-buffer overhead. |
| GPU bitmaps use a true LRU with a 32 MiB payload budget per renderer, retaining the existing 120-frame aging too. Oversized images still draw but are not cached. | Prevents bitmap retention beyond 32 MiB per renderer; actual driver allocation/metadata can exceed pixel payload. BGRA upload buffers remain temporary. |
| CPU glass pieces use a shared 16 MiB LRU; closed-popup pieces are removed immediately. Weak source identities prevent address reuse from matching stale pieces. Gallery skips fully clipped cards. | Caps retained glass pixel payload at 16 MiB and avoids offscreen glass allocation/upload. |
| Full decoded wallpaper is discarded after producing exact dock crops. Keep a small reload recipe for the popup fallback; ordinary popups still capture the live screen. | Frees `decoded_width × decoded_height × 4`: 7.91 MiB at 1920×1080, 31.64 MiB at 3840×2160, 126.56 MiB at 7680×4320, when decoded at those sizes. |
| Raw/composed icon pixels and popup data snapshots share `Arc` storage. Raw icon cache is byte-limited to 16 MiB LRU instead of 128 arbitrarily large images. | Removes repeated icon copies (256 KiB per extra 256×256 RGBA copy); bounds cache-owned payload. Live consumers can retain additional shared icons. |
| Screenshots retain the existing three thumbnails at at most 320×320. Directory scanning now retains only the newest three candidates; thumbnails/signatures are released when unused. | At most about 1.17 MiB of cached thumbnail pixels, plus no directory-sized candidate vector. |
| Finance snapshots share `Arc`; screen-time totals, stopwatch counts and screenshot presence avoid full clones/sorts during drawing. Weather retains the requested five days/120 hours; geocoding cache holds 32 locations. | Reduces per-frame heap churn; weather/geocoding remain small and bounded. CPU/RAM history was already capped at 120 samples and stopwatch laps at 100. Screen-time retains only the current day, preserving per-app totals. |

All production renderers already run on the UI thread and share its single Direct2D factory and shared DirectWrite factory/text formats. That sharing is retained; no unsafe cross-thread sharing of the single-threaded D2D factory was introduced.

Validation: `cargo test --no-fail-fast` passes (64 tests), including all widget/data-popup render paths, target release/recreation, forced cache eviction, hidden popup lifetime, individual telemetry disablement, non-overlapping jobs, and pixel-identical wallpaper reload at original/scaled decode sizes.

`cargo build --release` passes with `CARGO_TARGET_DIR=D:\Dock\target\ram-validation`. The normal output executable is locked by the running SmartDock process, so it was not replaced. The validated executable is `target\ram-validation\release\smartdock.exe`.

Risks: first use after hiding/eviction recreates resources; newly enabled workers load asynchronously (scheduler checks every 250 ms). GPU/network rate counters need their normal warm-up sample. In-flight blocking work finishes once after a widget is removed. Popup screen-capture failure now reloads the wallpaper file; this can add latency, and a missing/replaced file can affect that rare fallback. Cache limits may trade extra uploads for lower RAM on large/high-DPI configurations. Native shell/driver stack needs vary; 512 KiB workers have passed current tests but need field coverage. Render smoke tests verify successful rendering, not screenshot comparisons across every DPI/monitor/driver combination. Re-measure private bytes with the same layout after restarting into the validated build; the old ~260 MB process was not used as an after measurement.

No commits were made and `.git` was not accessed or modified.
